# 方案修订：精简 autorun 流程（如无必要，勿增实体）

> 状态：已实施。日期 2026-10-14。
> 后续修订（2026-10-14）：A6 实测后，进展页（`status.py`、`status.html`、`answers.tsv`、契约的 `阶段`/`计划契约`/`计划文件`/`花费` 字段）整体移除。原因：页面状态显示错误（收尾写成"完成（…）"被判为解析错误）、术语难懂、人工项重复；页面答复不被 tick 读取，只是第二套状态；停放与收尾的通知已覆盖"何时该看"，"进展"改由 Claude 直接读契约和日志回答。旧实现见提交 5750c37。以后若确需离开终端查看，再做只读页面：只看每份契约最新一次运行的停放，不做表单。
> 仓库：devflow `main` c4a4c49。
> 前置：`docs/plan-progress-view.md` 的第一部分已实施并提交（5750c37、2d8beb2、c4a4c49）。本修订取代其中"方案登记表"（决定 1）和"通知进度"（决定 6、9）两部分，其余不变。
> 依据：pstack 调研，以及用户确认的三点：
> 1. 删除登记表和 `register`，直接读取契约头部；
> 2. 删除 `--notify` 和通知进度，改为 tick 在停放和收尾时直接通知；
> 3. 新增 `arm.sh`，自动启动循环，自动防休眠。

## 背景

用户觉得武装太繁琐（"两个命令"、读一份长合同、手动启动循环和防休眠），而且刚实施的进展页又增加了几个实体。

对照 pstack：
- 只有一个入口，没有仪式。"无人值守"只是会话里的一句话。
- 合同就是几句话的提示词。
- 遵循三条原则：懒惰原则（同一个决定只放在一处）、先减后加、把教训编码进结构（结构上已经修好的，就只保留结构）。

有一点刻意不照搬：pstack 的安全靠信任，我们靠守卫。守卫保留。

## 计划

**目标**：
1. 按计划启动一次无人值守运行，你只需要做两件事：说一句话，然后看一屏摘要、回复"开始"。
2. 武装的关键步骤由脚本保证完成，不依赖模型记得每一步。
3. 进展页和通知的能力不变，但实体更少。

**非目标**：
- 不改 `guard.sh`、`check.sh`、`log.sh`，也不改 `.tsv` 的列格式；
- 不改 tick 每一轮的做法；
- 不做没有计划时的"一句话武装"（临时任务仍然现场商量合同，只是提供默认值）；
- 不覆盖 Codex；
- 不做第二、三部分（跨模型审查、对账）。

### 决定

**1. 删除登记表，直接读取契约头部**

- 删掉 `.devflow/roadmap.json`、`status.py register`、登记预览和 sha256 并发检查，以及"登记待同步"和登记错误。
- `status.py` 直接读每份契约的严格字段，再按阶段 → 计划契约 → 运行分组：
  - `阶段`
  - `计划契约`
  - `计划文件`
  - `花费`
  - 人工项行
- **运行顺序**：按该运行日志中第一条 `start` 行的时间排序。还没有日志的起草中运行排在最后，彼此按文件名排序。
- **阶段标题**：取计划文件的第一个一级标题。没有计划文件时，直接显示阶段编号。
- **人工项来源**：
  - 计划级：取计划文件里"人工项"标题下的表格，编号为 `<阶段>/<编号>`；同一阶段只读一次。
  - 契约级：取契约里的人工项行，编号为 `<运行>/<编号>`。
- **冲突提示**：同一阶段的不同契约指向不同的计划文件时，在页面顶部提示"计划文件不一致"，以最新运行的为准。
- **旧契约**：没有 `阶段` 或 `计划契约` 字段的契约，显示在"未挂接的运行"里。补上这两行字段即可挂接，不需要别的登记步骤。
- **代价**：还没有契约的后续阶段（比如 P3、P4）不会出现在页面上。

**2. 答复文件改名为 `.devflow/answers.tsv`**

格式和规则沿用原来的 `roadmap.tsv`：六列；phase 为 `user`；decision 写 `<编号> <动作>`；每个编号以最后一行为准；"撤回"让事项回到未处理。

**3. 通知改为在发生的那一刻发出**

- 删掉 `--notify` 和 `.devflow/notify-state.json`。
- tick 只在两个时刻调用一次 PushNotification：
  - 记下一条 `parked:` 行之后：发"等你决定 `<运行>/D<n>`：<一句话原因>"；
  - 收尾删除运行标记之后：发"`<运行>` <完成/部分完成/受阻>"，再加上待处理数量。
- 同一个 tick 里既停放又收尾时，合并成一条发送。没发出去也不重试，也不写进日志。
- `status.py` 保留 `status.lock`。这是内部的写入串行化，用户感知不到。

**4. 新增 `scripts/arm.sh <root> <slug>`，替代 SKILL 里的手写武装步骤**

用户回复"开始"后由会话调用。它依次执行：

1. **检查契约**：首行必须是契约标题；严格字段必须齐全（`阶段`、`计划契约`、`写入范围`、`受保护路径`、`分支`、`允许本地提交`、`预算`）；同一路径不能既在写入范围里，又在受保护路径里。
2. **检查工作区**：`.devflow/` 以外必须干净；当前目录下不能已经有这个 slug 的运行标记。
3. **准备分支**：分支不存在就从当前 HEAD 创建；已存在就切过去，但它的 HEAD 必须是当前 HEAD 本身或其后代，否则拒绝。
4. 把 `.devflow/` 写进 `$(git rev-parse --git-common-dir)/info/exclude`，已经有就跳过。
5. **写运行标记**，字段与现在相同：`session_id` 取自 `$CLAUDE_CODE_SESSION_ID`，`base_sha` 为当前 HEAD，并记录合同的 sha256，`deadline` 由预算换算。
6. **自检守卫**：
   - 确认 `~/.claude/settings.json` 里注册了守卫钩子；
   - 再模拟一次钩子输入（本会话、本目录、`git tag --list`），交给 `guard.sh`，确认它返回 2，也就是拦截。

   任何一步失败，就删除运行标记并退出，返回非 0。
7. **记 `start` 行**，证据写 `session <id>, base <sha>, guard self-test ok`。
8. 后台运行 `caffeinate -i -t <距截止时间的秒数>`。
9. 输出一屏摘要：分支、base、截止时间、写入范围、受保护路径、进展页路径。

脚本跑完后，SKILL 只多要求一步**实地验证**：运行一次 `git tag --list`，它必须被守卫拦下。如果没被拦下，说明钩子在本会话里没有生效，这时 `rm` 掉运行标记并报告，不能开跑。

基线由会话在给你看摘要之前跑好，并写进合同的"基线"字段；`arm.sh` 不跑完成条件。

**5. 自动启动循环**

实地验证通过后，会话用 Skill 工具调用 `loop`，参数为 `/devflow-autorun-tick <slug>`（动态节奏，不指定间隔）。如果宿主不允许模型调用 `loop`，就退回原来的做法：提示你输入这一行。

**6. 合同从计划生成，只给你看一屏**

- 武装时从计划的"契约拆分"一节生成合同，包括写入范围、完成条件命令、人工项和预算，写到 `.devflow/<slug>.md`。
- 给你看的不是整份合同，而是一屏摘要：
  - 做完的标准（逐条命令）；
  - 能改什么、不能碰什么；
  - 最长多久；
  - 基线结果；
  - 人工项数量；
  - 合同路径（想看全文时用）。
- 没有计划时，现场起草合同，并提供默认值让你修改：做完 = 项目测试命令，只能改源码目录。
- `devflow-plan/references/plan.md` 在原有提示之后补一句：契约拆分用一张表写，列为 `契约 | 写入范围 | 完成条件命令 | 预算`。

**7. 合同模板的严格字段**

- 写入范围和受保护路径中的每一项都用反引号包起来，例如 ``- 写入范围：`src/`、`docs/p1-records/` ``，这样 `arm.sh` 能逐项读取。
- `分支`、`允许本地提交`、`预算` 保持现有的写法，但改为固定格式。

**8. SKILL 正文**

autorun 的 Arm 一节改成"起草 → 一屏摘要 → 开始 → `arm.sh` → 实地验证 → 启动循环"，原来手写 `jq`、exclude、log 的步骤全部删掉。tick 删掉"每次 log 后运行 `--notify`"，改为第 3 条的两个时刻发通知。

**待定事项**：无。

### 风险

- **自动启动循环可能做不到**：如果宿主不允许模型调用 `loop`，就退回到"提示你输入一行命令"，这时你要做 3 个操作，而不是 2 个。
- **防休眠会持续到截止时间**：`caffeinate` 以截止时间为准，所以提前收尾后，Mac 仍会保持唤醒到截止时间；需要的话可以手动 `killall caffeinate`。
- **字段格式变严格了**：严格字段写错会被 `arm.sh` 拒绝，需要改好后再说一次"开始"。
- **守卫自检不等于实地验证**：它证明了守卫脚本、运行标记和 settings 的配置都对，但不能证明这个会话已经加载了钩子。所以 SKILL 里保留一次实地验证，也就是 `git tag --list` 必须被拦下。
- **A6 依赖你在新会话里操作**：在这之前，"新会话能否照做"仍然没有被验证。
