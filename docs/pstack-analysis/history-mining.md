## 3. 稳定偏好

- 中文；结论先行，"简单来说、举例"；逐条修订用 P0/P1/P2 加位置和最小修改；喜欢表格；方案保存到 docs（86 次）。
- 动手前先确认；排查常带"先不要改代码"；派发前先看交接提示词；一旦授权就做完。
- 提到子 agent 417 次；另开 session 交给其他 agent 约 570 次；要求独立评审 97 次。
- 要求真实或端到端验证 532 次；常直接给 Studio 地址（368）和截图（427）。
- 通用、最小、做减法；常问"业内怎么做"（108）。
- worktree 提到 273 次；提交按功能拆分。

## 4. 对 dflow 的含义

- **确认边界的张力**：B（168）、H（69）要求先停下确认；K（24）和"偏手动"的反馈要求别停。合起来是"开工前只确认一次方案和验收点，之后一直做到完成"。pstack 的"永不停下等人"不完全适合。
- **最大的空白**：追问解释（22%）没有任何技能覆盖，却是 I、E 类纠正的主要来源。
- **几乎没用的现有技能**：devflow-report、devflow-research；commit 很少被点名。

## 5. 局限

- Claude Code 只有 8-19 之后的数据；81% 来自 GameVistor，结论偏这条产品线。
- Codex 会话只读了头部 6KB，看不出技能是否真正执行。
- 关键词分类、去重只看前 200 字，数字是上限。
